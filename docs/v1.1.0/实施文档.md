# SuperPhoto v1.1.0 — 实施文档

> 目标：①安全移除视频超分，只保留图片处理；②接入 OIDC/OAuth2（SuperPhoto 作为被认证方/RP，认证方为 Personal_Sub2）；③优化用户管理系统；④优化异步处理逻辑。
> 依据的已核实事实见 `已验证事实.md`；进度与勾选见 `进度指引 .md`。
> 全程中文；最小改动、根因修复、遵循现有结构与风格；行为变化补最小测试。

## 0. 已确认的前置决策

- **Q1 视频移除**：应用层 + 清理 DB 列（删 video 列与 `video_quotas`）。
- **Q2 范围**：只改 SuperPhoto；Personal_Sub2 侧 OP 通电由用户另行处理。
- **Q3 登录**：双轨保留（用户名+密码 + 新增 OIDC）。
- **Q4 幅度**：任务 3/4 以兼容性修复为主，不破坏现有 `jobs.db`。

> 注意 Q1（删视频列，破坏性迁移）与 Q4（兼容修复）作用域不同：**删列仅限视频相关列**；用户表/任务表的其它结构保持不变。

## 1. 多智能体编排（并发≤2，最长等待 45 分钟，同一波次不碰同一文件）

```
Wave 1  视频移除        [A1 后端 .py] ‖ [A2 前端 web/]        零共享文件
   ↓ 主理人汇总+自测+放行
Wave 2  用户管理/异步   [C 用户管理 main.py/auth/config] ‖ [D 异步 worker/jobs]   零共享文件
   ↓ 主理人汇总+自测+放行
Wave 3  OIDC 接入       [E1 后端 oidc/main/config/db] ‖ [E2 前端 web/]           零共享文件
```

- 分波理由：`app/api/main.py` 是任务 1/3/OIDC 的共同核心，跨波串行才能保证不出现两个 agent 同改一文件；波内按“Python 后端 vs 前端 web”或“main.py vs worker.py”天然文件边界拆分，做到零冲突。
- 主理人（主 agent）职责：派发前给定精确文件边界与禁改清单；每波结束做导入冒烟、跑受影响测试、审阅 diff、裁决冲突，再放行下一波；全部完成后向用户汇总。
- 每个子智能体必须遵守：仅改分配给它的文件；不做无关重构/格式化；不执行 git 提交/推送；破坏性操作（删列）前先备份。

## 2. Wave 1 — 移除视频超分

### A1（后端 Python）— 独占：`config.py` `jobs.py` `api/main.py` `worker/main.py` `db.py` `tests/test_job_settings.py`
1. `config.py`：删除 `VIDEO_MAX_FILE_BYTES/WIDTH/HEIGHT`、`DEFAULT_VIDEO_QUOTAS`、`VIDEO_OUTPUT_FORMATS`、`VIDEO_INPUT_EXTENSIONS`、`VIDEO_INPUT_CODECS`、`VIDEO_TARGET_RESOLUTIONS`、`FFMPEG_BIN`、`FFPROBE_BIN`。
2. `jobs.py`：删 `validate_upload_type`、`UPLOAD_TYPES`；`validate_settings` 去掉 `upload_type` 概念与所有 video 分支（保留 photo 校验，签名尽量兼容——见下“契约”）；删 `estimate_video_output_bytes`；`estimate_processing_seconds` 去掉逐帧分支；`TARGETS` 删除所有 `1k` 项；`target_dimensions` 去掉 `1k` 长边。
3. `api/main.py`：删 `VIDEO_FORMAT_NAMES`、`upload_looks_video`、`store_upload_stream`、`probe_video`；移除 `create_uploads`/`create_modern_batch`/`api_estimate`/`retry_job`/`service_health`/`preview_file` 内的 video 分支；清理 `VIDEO_*`、`FFMPEG_BIN/FFPROBE_BIN` 的 import；`EstimateImagePayload` 去掉 `duration_seconds/fps/frame_count`。
4. `worker/main.py`：删 `process_video_job`；`process_job` 去掉 video 分支；`valid_output` 去掉 ffprobe 分支；`claim_job` 删除“单视频串行”子查询与相关 import（`subprocess/shutil` 若仅视频用则清理）。
5. **DB 迁移（含备份，破坏性）**：迁移前 `state/jobs.db` → `state/jobs.db.bak-remove-video-<日期>`；在 `init_db` 里新增一次性守卫迁移：若列存在则 `ALTER TABLE jobs DROP COLUMN <col>` / `ALTER TABLE uploads DROP COLUMN <col>`，列集合 = `upload_type,duration_seconds,fps,frame_count,video_codec,audio_codec`；`ALTER TABLE users DROP COLUMN video_quotas`。同步从 `JOB_COLUMNS`/`UPLOAD_COLUMNS`/`USER_COLUMNS` 与 `SCHEMA` 默认值里移除这些项。删列须在 `PRAGMA foreign_keys` 与 WAL 语义下测试通过。
6. `tests/test_job_settings.py`：删除 4 个 video 用例；保留/调整 photo 用例；确保 `validate_settings({}, 'guest')` 仍返回合法 photo 设置。

**契约提醒**：`validate_settings` 返回的字典目前含 `upload_type`；移除后要同步 `create_modern_batch`/`create_uploads`/`api_estimate` 对该键的引用与 DB 写入列。worker 读取 job 时不再有 `upload_type`。

### A2（前端）— 独占：`app/web/index.html` `app/web/app.js` `app/web/styles.css` `app/web/dialog-fixes.css` `app/web/enhancement-status.css`
1. `index.html`：删 `#uploadTypeChoices`（照片/视频切换）、`data-target="1k" data-upload="video"`、`data-format="mp4"/"webm"` 按钮及“上传类型”标签。
2. `app.js`：删文件末尾整段 video 猴补丁——`VIDEO_EXTENSIONS/VIDEO_MIME_TYPES`、重写版 `addFiles/renderFiles/syncUploadTypeControls`、`queuePreupload`、`syncVideoPermission`、`updateUploadCopy` 的视频文案、admin 的 `daily_video_quota`/`video_quotas` 注入、`jobRow` 的 video 覆盖；`state.uploadType` 相关逻辑简化为纯图片。
3. CSS：清理仅供视频控件使用的样式（谨慎，勿误删共用类）。

**验收**：`python -c "import app.api.main"`、`python -c "import app.worker.main"`、`pytest tests/test_job_settings.py` 通过；前端加载无 JS 报错、上传区仅剩图片。

## 3. Wave 2 — 用户管理（任务 3）+ 异步（任务 4）

### C（用户管理）— 独占：`api/main.py` `common/auth.py` `common/config.py` `web/app.js`
1. 访客额度前后端统一：前端 `renderIdentity`/`applyRoleUi` 统一读后端 `GUEST_DAILY_QUOTA`（3），消除“5/3”不一致。
2. 重构 `admin_update_user` 额度逻辑：以 `image_quotas`（`2k/4k/6k/8k`）为唯一事实源；清理 `resolution_1k/2k/4k`、`daily_image_quota` 这套 legacy 映射中错误套用到 image 的部分（视频相关字段随 Wave 1 已删）。保持对旧库缺列的容错。
3. `change_password` 成功后删除该用户其它 session（对齐 admin 行为），当前会话重新签发。
4. `delete_account` 改用 `clear_session`；`auth.py:require_admin` 用 `ROLE_ADMIN` 常量；`auth_me` 避免连接内再 `connect()`（把 capabilities 查询并入同一连接）。
5. `rate_limit` 增加空桶回收（防内存增长）；多进程共享限流不在兼容修复范围，仅加注释说明限制。
6. 访客 `daily=3/active=2` 收敛到 `config.py` 常量（新增 `GUEST_ACTIVE_QUOTA`），替换各硬编码处。

### D（异步）— 独占：`worker/main.py` `common/jobs.py`
1. 图片取消检查点：`process_job` 在 `update_progress` 返回 False（任务已被取消/租约丢失）时提前中止并抛可识别异常，避免算到底再丢弃。
2. 租约调优：评估 `LEASE_SECONDS`/心跳间隔，给 DB 抢锁与大图留余量（如 lease 60s、心跳 15s，或按耗时估算动态），复核心跳线程在异常/超时路径的收尾（`stop_event`/`join`）。
3. `estimate_processing_seconds` 移除视频逐帧后复核 photo 估算路径正确。

> C 与 D 零共享文件（C 管 main.py/auth/config/app.js，D 管 worker/jobs），可安全并行。`rate_limit` 属 main.py，归 C。

**验收**：导入冒烟 + `pytest tests/test_job_settings.py`；模拟：提交任务→取消 processing→worker 应尽快中止；admin 改额度/改密/禁用→其它会话失效。

## 4. Wave 3 — OIDC 接入（任务 2，RP，双轨）

### E1（后端）— 独占：`common/oidc.py`(新增) `api/main.py` `common/config.py` `common/db.py` `common/auth.py`
1. 新增 `app/common/oidc.py`：discovery 拉取+缓存、PKCE(S256) code_verifier/challenge、`state`/`nonce` 生成与校验、授权 URL 构造、code 换 token（token 端点 HTTP Basic 传 client_id/secret）、id_token 验签（用 discovery 的 jwks，校验 iss/aud/exp/nonce）、userinfo 拉取。全部超时/异常有兜底。
2. `config.py`：新增环境变量 `OIDC_ENABLED`、`OIDC_ISSUER`（或 `OIDC_DISCOVERY_URL`）、`OIDC_CLIENT_ID`、`OIDC_CLIENT_SECRET`、`OIDC_REDIRECT_URI`、`OIDC_SCOPES`（默认 `openid profile`）。缺失关键项时 `OIDC_ENABLED` 视为假。
3. `db.py`：新增表 `oidc_identities(id, issuer, sub, user_id REFERENCES users(id) ON DELETE CASCADE, created_at, last_login_at, UNIQUE(issuer, sub))`；不改 `users` 现有结构。首登自动建 user：`role='user'`、`password_hash` 写不可用哨兵（如 `'oidc$disabled'`，`verify_password` 天然返回 False）以兼容 `NOT NULL`。
4. `api/main.py`：新增 `GET /api/auth/oidc/login`（生成 state/nonce/verifier，存短时 server 侧或签名 cookie，302 到授权端点）、`GET /api/auth/oidc/callback`（校验 state、换 token、验 id_token、按 `(issuer,sub)` 查/建 user 并关联、`rotate_session` 建本地会话、迁移匿名 uploads）；`/api/auth/me` 增加 `oidc_enabled` 字段。用户名+密码/邀请码路径保持不变。
5. 复用 `auth.py` 的会话机制（`rotate_session`/`set_session_cookie`），不重复造轮子。

### E2（前端）— 独占：`app/web/index.html` `app/web/app.js`
1. 登录弹窗新增“使用 Personal_Sub2 登录”按钮，跳转 `/api/auth/oidc/login`；`state.me.oidc_enabled` 为假时隐藏该入口。
2. 回调返回后刷新 `loadMe`/历史；错误提示复用 `toast`。

**外部前提（用户负责，非本仓库）**：Sub2 侧开 `oidc_provider.enabled`、生成并激活签名密钥、注册 SuperPhoto client（回调 https）；若 issuer 域名 ≠ `auth.taffy.edu.kg` 需在 Sub2 解冻常量。

**验收**：`OIDC_ENABLED=false` 时前端无 OIDC 入口、其它功能不受影响、导入冒烟通过；`OIDC_ENABLED=true` 且配置齐全时，`/api/auth/oidc/login` 能构造正确授权 URL（含 `code_challenge`/`state`/`nonce`），callback 逻辑单测（可 mock discovery/token/jwks）。
